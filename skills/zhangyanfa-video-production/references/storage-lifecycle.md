# 素材归档、缓存与瘦身

## 1. 先审计，后清理

先生成按大小排序的清单，标记每个大文件的用途、是否可再生、是否仍被工程/清单绝对路径引用、是否已有通过验收的替代成品。没有引用证据时不得删除。

## 2. 必须保留

- 用户原始录屏、官方/用户提供图片与原始音频；
- 最终文案、最终字幕、最终配音与修音母版；
- 当前通过的 A/B/C 母版、BGM和封面；
- 源清单、哈希、匹配表、审核包、render plan、chunk/concat 收据和 QA；
- 可重建成品所需的脚本、HyperFrames工程与少量关键代理；
- 剪映当前依赖的稳定普通文件或硬链接。

## 3. 通常可清理

在确认未被引用且成品已验收后，可处理：

- 旧的低清预览、重复联系表和已失效审核图；
- 能从原源与清单重建的中间代理；
- 已被新收据取代的旧分块和 `.partial` 文件；
- 模型临时下载、浏览器渲染缓存和重复转码副本；
- 旧 attempts 中未被正式 manifest 选中的配音候选。

优先移动到按日期命名的可恢复目录或系统废纸篓，确认工程重开和当前母版 QA 后再永久删除。

## 4. iCloud与系统目录

- 不直接清空 `~/Library/Application Support/CloudDocs/session/`。它由 CloudDocs 管理，录屏样文件可能是同步会话内部对象，不是普通项目副本。
- 不整体删除 `~/Library/Caches/`。先按应用和可重建性分类，关闭相关应用后只清理明确缓存子目录。
- 把高频代理、OCR帧、浏览器缓存和渲染 scratch 放在非 iCloud 本地目录；只同步源、清单、通过的审核证据和交付成品。

## 5. 移动录屏

把新录屏归入共用素材库时：

1. 先探测规格并计算 SHA；
2. 根据任务/章节命名，不用下载时间作为唯一语义；
3. 检查已有工程是否硬编码旧绝对路径；
4. 若已被引用，移动后在旧位置保留同名符号链接，或完整更新清单并重做哈希绑定；
5. 复查源路径、时长、UID和可解码性。

## 6. 清理验收

清理前后分别记录总大小、文件数和可用空间。重新打开当前工程，验证源文件可访问、当前母版仍能全解码、关键清单路径有效。报告删除/移动了什么、节省多少空间、是否可恢复。
