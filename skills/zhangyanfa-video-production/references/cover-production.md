## 1. 封面承诺

先用一句话写清：观众一眼要认出谁/什么，以及本期要他们感受到哪一种关系、冲突或命题。主体控制在一至两个视觉中心。

“有人物、有冰雪、有标题”只说明元素齐全，不代表封面成立。背景仅与地区或属性相关也不够；只要存在能承载本期核心关系的具体剧情镜头，就优先使用该镜头语法，而不是泛用的左右对峙或站桩合照。

封面承诺必须是本期独有的可视命题。上一期通过的角色组合、漂浮姿态、救援动作或影域背景只能作为被明确分类的风格参考，不能因为“延续系列感”自动成为本期镜头。若换掉标题后仍像上一期封面，先重写承诺和镜头，不继续精修。

## 2. 参考职责与来源冻结

每张参考图只能承担已声明的职责，至少区分：

- `identity_model`：人物身份、年龄感、性别呈现、发型、发色、瞳色、脸部特征、服装结构和标志物；
- `shot_camera`：机位、景别、姿态、人物相对位置、运动方向、留白和空间关系；
- `style_render`：游戏感、材质、光照、色温、线条、体积雾和后期质感；
- `typography`：只记录本地字体、标题层级和安全区，不交给图像模型生成。

不能因为“参考图都给了”就让一张人物模型图同时替代剧情镜头，让一张实机截图同时替代人物身份图。建立 `cover_sources.json`：

```text
asset_id
canonical_identity
source_path
source_sha256
source_kind
reference_role
authorization
allowed_transform
shot_anchor_note
crop_note
review_status
```

`authorization` 记录 `official`、`user_provided`、`user_authorized_generation` 等来源权限。生成资产另存提示词、生成时间、所用参考、输出 SHA 和淘汰理由。

## 3. 精确主体与人物身份硬门

先按主体类型决定路线：

- 官方角色、武器、UI、图标和其他需要一眼精确识别的对象，默认使用官方/用户资产做确定性前景；
- ImageGen 默认只生成背景、气氛、光效或用户明确批准的完整场景，不重画官方武器和UI几何；
- 五把武器、五件道具等并列展示，优先使用官方图标/切图平铺和统一排版，不让模型重新发明透视、刃口、弓弦或配件；
- 只有缺少可用官方主体，且用户明确授权完整场景生成时，才允许生成精确主体，并继续执行更严格的身份验收。

精确主体和人物身份是第一门，优先于构图、颜色和标题。逐项对照参考检查：

- 角色是否就是用户点名的人，而不是同地区、同阵营或相似配色的另一人；
- 年龄感、性别呈现、发型/发色、瞳色、脸部轮廓和剪影是否匹配；
- 服装主结构、领口、袖口、配色、标志物和体型比例是否可一眼对应；
- 手、眼、肢体数量、四肢连接和遮挡关系是否正常。
- 武器轮廓、刃口、护手、弓弦、枪尖、比例和元素标志是否与官方资产一致；不得用“风格化”解释变形。

身份错位属于 P0。右边要求“白沙皇”却放入“冰之女皇”时，无论背景、排字或精修多漂亮都必须整版退回，不能靠标题解释。

## 4. 叙事镜头硬门

身份通过后，检查画面是否在讲本期，而不只是展示两个人：

- 优先锚定真实任务中的关键镜头、动作或空间关系；
- 人物的距离、朝向、动作和视线必须承载题眼，如失重靠近、分离、对峙、追随或坠落；
- 泛用冰宫、风雪、光柱等只能承担气氛，不能替代叙事动作；
- 左右各站一个人的静态对称构图默认视为“人物海报”，除非本期命题本身就是正面对决；
- 标题留白应由镜头自然提供，不能为了塞字把关键人物缩成装饰。

先做无文字小图，缩到平台列表尺寸，确认人物关系和题眼无需标题也能成立。若去掉文字后只剩“两个角色在一个相关背景里”，或主要被读成与本期无关的救援、恋爱、对峙与合影，叙事镜头门未通过。

## 5. 同场景一致性硬门

把两张角色立绘贴到同一张背景上，不等于两人处于同一空间。逐项检查：

- 光源方向、阴影方向、色温和明暗对比一致；
- 机位高度、透视消失点、景深和人物尺度一致；
- 线条粗细、材质、边缘锐度、噪点、压缩质感和渲染风格一致；
- 地面、雾、粒子、遮挡和环境反光真实地作用在所有主体上；
- 人物之间的空间距离与姿态相互解释，而不是各自朝着不同镜头表演。

如果官方切图无法跨过同场景门，不要继续增加暗角、辉光、雪花或调色来掩盖拼贴感。改用一张完整官方剧情帧，或在用户明确授权后依据身份、镜头和风格三类参考重新生成完整场景。

## 6. 生成路线边界

默认路线仍是官方/用户图的确定性合成。只有用户明确要求 ImageGen、风格化角色或完整场景重渲染时，才允许生成角色；这项授权不自动允许重画官方武器、UI或图标，除非用户明确要求它们也参与生成。

生成路线按以下顺序：

1. 冻结 `identity_model`、`shot_camera`、`style_render` 三类参考及其 SHA；
2. 先生成无文字的 `16:9` 场景测试，不让模型写中文；
3. 先审身份，再审叙事镜头，再审同场景一致性；
4. 只对已定位的小缺陷做定向修复；身份、年龄感、人物数量或镜头关系错误时整张重做；
5. 通过后冻结无字底图，再由本地排版加入标题；
6. `16:9` 的身份、命题镜头和同场景门通过后，才为其他画幅重新生成或重新构图并单独验收。

用户授权生成只改变“可以使用的手段”，不会降低人物保真标准。不得用“原神风”“风格化”解释错误人物、错误服装、崩坏手部或镜头关系改变。

## 7. 文字与多画幅

标题用本地字体排版，不让图像模型生成汉字。先在缩略图尺寸检查题眼、人物脸和标题，再看大图细节。边框、发光、分区和小图只服务层级，不能修复身份、镜头或拼贴问题。

分别设计 `16:9`、`4:3`、`3:4`。允许共享身份、镜头意图和视觉主题，但每个画幅重新安排人物、动作中心、标题和安全区；不得把16:9机械裁成另外两个比例，也不得在16:9尚未通过时同时生成三套错误方向。

## 8. 验收与迭代记录

验收顺序固定，前一门失败时不进入后一门：

1. `identity_pass`：每个人物与身份参考一眼对应，官方武器/UI几何与源资产一致；
2. `shot_pass`：镜头直接承载本期关系或命题；
3. `same_space_pass`：光照、透视、材质、尺度和环境作用统一；
4. `text_pass`：标题无错字、断字和模型伪字，缩略图可读；
5. `edge_artifact_pass`：主体边缘、卡片间隙和背景无意外横线、接缝、抠图白边或生成伪线；
6. `ratio_pass`：每个画幅独立成立，无关键裁切；
7. `source_pass`：来源、授权、参考职责、`exact_subject_route` 和输出逐项可追溯。

保存通过版、无字底图、源图、合成工程、`cover_sources.json`、验收清单和被淘汰版本。被淘汰版记录明确原因，例如 `wrong_identity`、`generic_shot`、`collage_mismatch`、`style_mismatch`、`bad_crop`，不要只写“效果不好”，也不要覆盖唯一可回退成品。

`shot_pass` 必须附上冻结的封面承诺和无字缩略图；标题文案不能作为镜头成立的证据。ImageGen首次输出若年龄感、性别呈现、人物数量或身份错误，状态只能是 `generated` 或 `rejected`，不能先排字、多画幅再回头修身份。

Workflow v3 的 `cover/review_manifest.json` 还要记录 `approved_artifact_path`、`approved_artifact_sha256` 和 `approval_ledger_id`；该 ID 必须指向 `cover_review`。用户通过后重新导出、去线、改色或替换任何主体都会使旧批准失效，必须重新展示最终16:9文件。
