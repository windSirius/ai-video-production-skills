# VoxCPM2 参数对比与听感选择

用于起句抢拍、断句不自然、音色不稳，或明确要求提高合成质量的局部试音。先定位正文、发音代理、韵律和信号中哪一项有问题，再做有边界的对比。不要每一期无理由重跑参数网格。

狐久已由用户选定 E 为后续标准，具体值见[固定生成参数](foxjiu-generation-profile.json)。E 的听审偏好优先于未经试听的高步数候选；以下网格用于确有问题时的定点排查，不取代已经选定的默认。新输入绑定本期冻结的 `generation_profile` 副本，预检会核验其 SHA、参数及种子策略；不能修改参数后仍宣称使用 E。不同设备或模型版本需要重新验证，不把本机效果直接外推。

## 参数的实际含义

先核对当前安装源码的 `VoxCPM._generate` 签名及模型实现，记录版本或 commit 与关键源码 SHA。网页示例可能比本机新，不能直接把新参数传给旧 API。

| 项目 | 初始选择 | 如何使用 |
| --- | --- | --- |
| `inference_timesteps` | 10 | 扩散采样步数；更多步增加求解工作，可能改变细节，也可能产生更差候选。不是语速旋钮。 |
| `cfg_value` | 2.0 | Classifier-Free Guidance 强度；改变有条件与无条件预测的组合，不代表“质量等级”或音量。 |
| `normalize` | `false` | 自动文本规范化可能改动送入模型的文本；正典和发音代理应由输入清单管理。 |
| `denoise` / denoiser | `false` / 不加载 | 这里处理的是参考音频，不是成品降噪。狐久固定参考不允许在试音中暗自换成处理后的音频。 |
| `retry_badcase` | 显式 `false` | 受控对比关闭隐藏重试；重做必须产生可追溯的新 attempt 和种子。 |
| 参考模式 | 当前已验证模式 | 狐久保持固定原件与逐字参考文案；Ultimate Cloning 的 prompt/reference 都使用相同原件。 |

依据：[官方 Python API 示例](https://github.com/OpenBMB/VoxCPM#python-api)、[API 实现](https://github.com/OpenBMB/VoxCPM/blob/main/src/voxcpm/core.py)、[CFG 求解实现](https://github.com/OpenBMB/VoxCPM/blob/main/src/voxcpm/modules/locdit/unified_cfm.py)。10 步 / CFG 2.0 是核对版本时的默认示例；升级后重新核对，不能沿用过期签名。没有确认实现的 `temperature`、`top_p`、`speed`、`seed` 等参数不得自行添加；旧 API 的种子通过实际使用的 Python / NumPy / Torch 及设备 RNG 设置并记录。

## 最小对比流程

1. **先固定文本。** 用户要求“如果”改为“如果说”这类可听出的增字，属于正典修改，创建新稿版本并记录原话；不能藏在 `generation_text`。正文其余内容不变。试读候选与正式已批稿分别标记，旧稿批准不能自动授权新候选整批生产。
2. **固定其他条件。** 同一完整开场生成块、同一参考及转录、同一模型权重/精度、同一随机种子、相同规范化设置。优先 120–180 个可发音字符，保留起句后的上下文。可以为播放导出第一句摘录，但不能把碎句合成冒充正式长块试配。
3. **有边界地变化。** 常用第一轮为：当前设置；10 步 / 2.0；16 步 / 2.0；16 步 / 1.5 或 2.5。第四组只改变 CFG，选择一个方向即可。删除重复配置，通常总计 3–4 组。8 步仅在它是旧设置时作为对照，不称为默认质量档；16 步仅是待验证候选，不自动升级为全局默认。
4. **单工生成并保留证据。** 同一模型会话顺序生成；逐组保存不可变 WAV、输入清单 SHA、生成文本 SHA、模型/参考绑定、种子、参数、实际耗时和内存记录。试音来源在生成前校验固定参考；正文、参考或参数变化使旧开头听审结论失效。失败候选也保留，禁止覆盖或只报告最好的那次。
5. **先排除明确错误。** 全段解码、实际 PCM 有限性、峰值、异常静音、漏字/多字/顺序和尾字；用第二识别器或真实听审裁决专名/同音字。ASR 时间戳可帮助定位“如果说”，不能精确证明音素时长或自然度；全文相似度和较长总时长也不是韵律 PASS。
6. **同条件听感选择。** 听完整开场块，重点比较前 3 秒、主语专名、句间停顿、句尾、音色与自然度。若响度差异影响判断，可另导出共同目标响度的试听副本，只作固定增益调整，明确标注并保留原始绑定；不以压缩、拉伸或添加静音掩盖问题。若无法实际听音，写 `awaiting_actual_audition`，交付具体音频供有能力的审核者选择，不能假填听审。
7. **冻结选择，验证适用范围。** 记录选择理由、审核者、实际听过的音频 SHA 与配置；明确是本期开场偏好，还是在多个不同文本上也验证过。差异细微或怀疑种子偶然性时，只对前两名换一个共同种子复核，不无界重试。开场获选后仍需在后续每块执行词面和信号 QA，并完成最终母带完整 1× 试听。

停止条件：一轮有限候选完成后，已有可靠听感选择则固定配置继续；有明确失败只修相关候选；听感能力缺失则交付候选等待实际审核。不要为了制造“参数已提高”的结论一直加步数。

如果起句仍显得快、不同步数的节奏定位又相近，先检查经用户授权的措辞、合法语义边界及种子变化，不继续单向增加步数。更高 CFG 若带来漏词、重复或尾字不清，回退到有证据支持的候选；不能因为峰值正常就保留。一次样本的失败不构成对该参数值的永久禁用。

## 参数记录与整批衔接

项目保存 `parameter_trials.json` 和对比报告。每组包含 `trial_id`、`source_manifest` / `sample_audio` 的路径与 SHA、`seed`、`inference_timesteps`、`cfg_value`、机器检查、实际听审和生成耗时。未选候选标记 `selected=false`、`bulk_authorized=false`；项目样本、私人路径和实际数据不写进可分发 skill。

选定后为正式生成创建不可变 `source_manifest`，采用确实听过的配置。若试音清单明确标注仅实验，不可悄悄把其审批扩展为整批：保留实验记录，在正式输入下重新绑定同一音频与真实听审证据，并经过 `verify_voice_reference.py --phase bulk`。任何重生成或音频处理后的新 SHA 都必须重新检查和试听。

## 内存与速度

采用一个模型进程、顺序候选和轻量监控；等待人工选音时卸载模型，勿长期占用统一内存。MPS 的已分配/驱动内存、进程 RSS 和系统内存压力分别记录，不把较小的 RSS 当成模型总内存。遇到持续高压力先停自己的任务并报告。

缓存容量可在证明输入加最大生成长度不超限的前提下缩小；容量不足应失败，不能截断尾字。不要以降低推理步数、精度、缩短成碎句或省略 QA 来解释“低内存”。实际耗时应区分模型冷加载、参考编码、生成和 QA；不同音频长度要同时报告 RTF，不能把第二组少了冷启动的时间误当成参数更快。
