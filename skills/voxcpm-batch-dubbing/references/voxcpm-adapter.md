# VoxCPM Gradio 适配

## 字段

- `Transcript of Reference Audio`：参考音频实际说出的原文；
- `Target Text`：本次需要合成的新文字；
- Ultimate Cloning 模式下 Control Instruction 通常不可用。

不要把整篇口播稿填进参考音频转写栏。用户已经准备好浏览器状态时优先复用；每次界面变化以后重新读取状态，不复用旧索引。

生成完成后先确认结果 URL 已变化，再立即保存 WAV；下一次生成可能覆盖页面中的上一条结果。长段落被截断、尾字丢失或服务断开时，只重做相关段落，并记录 attempt。

优先使用稳定的本地 API 或下载 URL；只有确实需要时才通过界面操作。Apple Silicon 上长段推理可能持续数分钟，应分段轮询并向用户报告进度。

## 生成块长度与语义边界

正典单元用于证据、定位和逐字覆盖；generation block 才是一次送入 VoxCPM2 `Target Text` 的文本。默认把相邻完整语义单元按顺序打包到约 150 个可发音字符，优先范围为 120–180，soft max 为 200。可发音字符按 NFKC 后的 `generation_text` 统计字母和数字，忽略空白与标点；外文或数字应先使用已批准的发音代理。

- 少于 100 个可发音字符时写入 short warning，并优先与相邻完整语义单元重平衡；
- 少于 60 时标为 very-short，只能作为有明确原因的例外，并增加候选、词面、接缝和定点人工试听；
- 181–200 可以作为超出优选范围但仍在 soft max 内的完整语义块；
- 单个不可再分的正典单元超过 200 时保留为 over-soft-max 例外并告警，不得按固定字符位置截断。

只在段落、句号、问号、感叹号、分号、英文句末标点或省略号等合法语义边界切分和打包；不得在普通逗号处或词语内部截断。说话人变化、独立引文或章节边界应由上游标记为强制断点。正典单元的 source span 可以跳过段间空格或换行，但 gap 必须完全由 Unicode 空白组成并显式记录原文、span 和 SHA；任何非空白遗漏、错位或 span 重叠都必须失败。尾块过短时，移动完整正典单元或在不超过 200 的前提下与前块合并，不改写、不填充、不重复正典。使用 `../scripts/plan_generation_blocks.py` 可生成带长度状态、告警、source span、separator gap 证据和 SHA 的确定性计划。
