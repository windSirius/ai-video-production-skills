# 狐久：确实找不到的剧情画面转 B 轨

用户长期决定（2026-09-24）：“以后如果有些画面和剧情真的找不到，就统一B轨”。本期另明确：黑框统一用 B 轨卡片；厄里那斯优先找星阳希录屏，找不到也用 B 轨。对后续狐久项目有效，不追改旧交付。

## 何时采用

- 用户点名要求 B 卡时直接采用，不再为该项持续找原生界面。
- 其他项先查共用库、正确版本/任务名和用户优先来源；对有希望的候选核对真实标题、发布者、分P及目标对白。检索确无适配画面、源不可取得或只有无法使用的画面时，记录已查范围与原因，转 B。不要反复换关键词无限搜索，也不要把搜索摘要里的推荐视频当成当前视频。
- 这项授权已经包含可靠原文的转录卡，无需每期、每条重复申请同一种替代许可。它不等于新卡片的版式、内容、时序已经审看通过。

## 怎样落实

1. 保留用户冻结的配音、字幕和帧时钟。记录 `cue_id`/帧区间、未取得的原画面、检索记录、转 B 理由及本条长期授权或本期明确决定。
2. 核实文字来源、语言、任务/条目定位、版本与原文。B 卡注明出处；数据库转录不称原生游戏截图，作者推断不冒充官方原文，beta 不冒充正式服。可靠文字也未取得时，保留事实缺口，不能编造卡片来清零。
3. 将该条**直接证据呈现**的责任改到 B：`target_track=B`、`status=card`。另记 `resolution_status`，区分“授权方案”“文字已核”“卡片已制”“审看通过”。只有文字和可执行呈现材料齐全才能关闭对应的素材缺口；选用卡片本身不等于制作完成。
4. A 轨仍用叙事相关的游戏/CG环境或反应镜头承接，标明上下文作用；直接事实由 B 卡证明。该区间不再以“缺少同一事件的原生 A 镜头”反复阻断，也不把 A 上下文镜头伪报成该人物/事件直接可见。卡片不烘进 A、不取消 A 时间覆盖、不以无关战斗或假人物凑数；若连相关 A 上下文也没有，保留这项真实缺口。
5. 容量表分别计算 A 上下文镜头与 B 证据条目，B 卡不计为 A 独立物理镜头。转轨决定传递给逐字幕计划、身份核验、P0表和容量报告，沿用固定简体新青年体考据卡样式及正常分轨审核。

交接记录至少包括：`requirement_id`、`cue_ids`、`start_frame/end_frame`、`original_visual_request`、`search_receipts`、`fallback_reason`、`user_authorization`、`evidence_refs`（路径及SHA/来源URL/条目定位）、`target_track`、`status`、`resolution_status`、`a_context_plan`。不要把“画面找不到”扩大成“剧情不存在”。
