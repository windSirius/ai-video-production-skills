# B/C 轨与审核包

## 职责

- B轨证明或解释：原文、任务台词、书籍、档案、关系图、时间线、比较卡、经批准的剪影。
- C轨维持少量跨段落象征、空间或关系提示，不承载必须停留阅读的正文。

每个 B/C 资产都要回答“它证明或解释了什么”；只为了丰富画面时删除。

狐久项目制作或返修卡片时，先读 [新青年体考据卡规范](foxjiu-evidence-card-style.md)，调用配套 JSON 与 renderer。它固定用户选定的字体和尺寸，并保留原文、转录、转述与本期推测的区别。

## 观众版本

证据卡默认只有一条短标题、一张来源/引文和一个高亮重点。来源路径、审核编号、风险提示和内部说明写在 ledger，不烧进观众画面。阅读时长由文字量决定，相邻页面默认硬切。

高亮框按原图像素坐标与实际 contain/pad 变换计算；不同截图不能共用一个全局框。每页边界检查 `-1/0/+1`，不得让出入页在同一帧同时透明为零。

## 人物与来源

剪影或人物卡使用官方/用户资产确定性制作。原图、处理结果、身份、方向和 SHA 一并审核。象征替代必须明示其不代表已确认外形。

## alpha 与绿幕

在计划中冻结 `alpha_master` 或 `green_screen_master`。绿幕模式使用全帧统一纯绿背景，不给单个透明素材加绿色矩形；alpha 模式必须实际验证下游能正确读取透明度。

## 分轨审批

A、B、C 审批互相独立。B/C 审核包列出所有 active range、原始资产、观众处理、时间、身份和阅读时长；未展示的资产不能因同类样式已经通过而自动进入正式轨道。
