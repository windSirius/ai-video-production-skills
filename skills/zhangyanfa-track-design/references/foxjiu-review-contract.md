# 狐久审核页与选镜约定

用户在第三期《原神下一张新地图，可能在过去》明确要求固定正在使用的审核框架，并在整片选镜结束后限制复用。后续狐久项目默认沿用本约定。

## 固定 WebUI

基准是 [review-ui-v1](../assets/review-ui-v1/framework_manifest.json)，HTML、CSS、JS 的原始快照保存在同目录。保留页头 A/B/C/BGM 入口、左侧字幕检索、主预览、逐句和连续播放、候选方案、头中尾证明、分轨叠看与绿幕切换、审核草稿保存。不得按个人偏好重新设计或另换框架。

新项目只接入其字幕、时间轴、候选、证据、音频、来源路由和项目文字。可以修复播放或数据兼容问题，但要保持布局和交互。项目编号、cue 数、时长、端口、文件路径及 localStorage 命名空间都是数据，不能照抄第三期数值。新版选镜必须使用新 plan revision 的草稿命名空间，保留旧稿，不把同名 A/B/C 选择自动当作新版已审。草稿永远不是最终批准。

## 整片复用

所有选镜完成后，先审计当前选中方案，再提交审核。按实际物理镜头、原始源区间及可见构图统计；同一画面的别名、跨文件摘录、裁切、缩放、倒放或调色均合并计数。连续源区间因数据分段而跨两个 cue 的情况也不能当作新镜头。

全片最多保留 4 组有叙事目的的复用，目标是 3–4 组以内；一组以首次使用和一次回扣为常规。每组记录每次时间、原始来源、作用和次数。不能为达到计数而把单组循环很多次。先保留关键物件和结尾情绪回扣，其他重复从同场景未用动作、反应、环境或新的合格素材中替换。

v2 默认硬上限为最多 4 组、每组最多 2 次；无需刻意凑满回扣。提交时总控重新读取实际选镜数据计算，不能用旧的相邻复用 PASS 替代。合法的风格变更须先由用户明确改变冻结契约，不由制作方扩大上限。

每次新版送审，必须在现有框架的数据入口提供差异摘要：原/新版本、改动 cue 与原物理镜头、替换理由、哪些旧审批仍有效、哪些必须重审、当前 BGM ID。旧版可回查，新版命名空间隔离；不要重画 UI 来做这份摘要。全长 A 和前十秒联播都在实际冻结旁白上检查后才开放送审。

审核报告必须同时列出重复组数、额外出现次数、每组次数、相邻重复、源区间重叠、近似画面人工复核结果和修改前后比较。素材不足时补充素材；不要用无关镜头、假唯一 ID 或降低语义匹配掩盖缺口。

## 开头

前 10 秒优先使用纯 CG / 官方叙事动画。画面变化应有可读的因果或问题推进，包含不同场景、景别及动作。不能用同色背景的连续人物站桩充当 eye-catching 蒙太奇，也不能为了快而打碎关键动作。最终按冻结旁白实听实看，检查每次切换是否带来新信息。
