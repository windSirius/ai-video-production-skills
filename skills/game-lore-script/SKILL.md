# 游戏剧情考据口播稿

把研究写成一篇能听懂、能配画、经得起核对的口播稿。判断力和证据先于固定模板；机检负责找风险，不能替作者决定一句中文是否自然。

总纲只有一句：先把人和事说清，再让概念参与解释；先让证据支持判断，再让人物选择承载价值。前半句约束句法与论证，后半句约束叙述立场与升华次序。

## 工作路径

先读取本期 `workspace_paths.json`，遵守[统一目录与素材规范](../zhangyanfa-video-production/references/workspace-layout.md)。稿件与审校放 `script/vNNN`，证据与研究放 `research/vNNN`。这里的 kind 由路径 resolver 解析，不是自行创建英文目录。 所有新版本先分配目录，再写文件；不自行发明另一套阶段路径。旧期 `legacy_indexed` 工作台用于导航，不视作新生产目录或新的审批权威。

## 输入与边界

开始前确认本期主题、观众看完以后应当明白什么、字数或时长上限、已有证据、反证、素材覆盖和素材缺口。优先读取上游 `evidence_ledger.tsv`、`source_coverage.json` 或同等文件；不要在本技能里重新下载、OCR 或建立镜头库。

处理事实或版本冲突时，读 [references/evidence-and-authority.md](references/evidence-and-authority.md)。任何新稿、改稿、压缩或正式审校，都必须完整阅读 [references/traditional-chinese.md](references/traditional-chinese.md)；这份手册同时保存用户已确认的反欧化正反例、叙事经验、措词标准和语料核验方法。涉及整稿创作、重写、压缩或整体审校时，同时读 [references/author-voice.md](references/author-voice.md)，先检查承诺、信息推进和推导，再润色句子；不能等用户指出“像 AI、絮叨、重复”才执行。

## 冻结前必须满足的条件

1. 每个关键判断都能在原文或画面中找到依据，并标明页码或时间码；推断不得写成官方明示。
2. 全篇只回答一个核心问题。支线只有在会改变最终结论时才进入正文。
3. 每段原则上都应推进一项新内容：交代一件事、引用一段原文，或说明一层因果、后果或判断。若没有新事实，也必须帮助观众理解前文、承接上下段或完成必要的情绪转折；否则删除。狐久推断类口播按下述「连续叙事」规则安排反证。
4. 中文必须主干清楚、搭配自然、修饰得当、指代唯一，段间与段内逐句都有清楚的承接。论证段默认采用较明确的讲解强度，不能只有段首连接词。选词时还要分清所写的是人、众生、物件还是抽象概念，并确认它是旁白、人物台词、机构口吻，还是逐字引用的官方原文。狐久旁白不用“有分量、多了一层分量”等泛化评价，按语境写清关键、核心、重要性或具体作用。全稿必须完成一次 1× 朗读。
5. 每段必须有可执行的画面需求。现有素材不足时记录 P0 缺口；可以先冻结稿件，但总控不得让未解决的 P0 缺口进入正式配画。
6. 用户明确批准当前稿件后，才能冻结 `script_manifest.json`。稿件、纯文本或证据变化后，旧批准立即失效。

## 第二人称：`hook_only`

- 开场第一个口播段可以用第二人称提出本期核心问句，例如“你真的看懂这场布局了吗？”
- 钩子之外，叙述层默认使用“我们”或第三人称。引文中的“你/你们”不计。
- 正文若无缘无故反复称呼观众，稿件不能通过审校；钩子使用第二人称本身不是错误。
- 钩子不必每期都用问句。现场、原文、结论或结果先行同样有效，以本期主题为准。

## 工作流

### 1. 立论

先用一句话写清本期要回答什么，再用一句话写出最终结论；随后在研究材料中列出最有力的证据、最强的反证、必要的因果和不能越过的边界。研究必须检查反证，不代表口播必须逐条念出。与最终结论无关的旁证留在研究附录，不写进口播正文。

将拟用标题、钩子和结尾答案并列检查：对象、范围、预设与确定性必须一致。标题里的“重新、终于、唯一”等不能暗含正文尚未建立的前提；发现承诺大于证据时，补证据或收窄承诺，不能只加强语气。

跨期优先查已有证据索引，但重新核对版本、原文位置和是否仍成立。保留原文版本与引用定位，给旧预测登记命中、收窄、未决或失效，不能把旧期推测自动升级成官方事实。长期索引是可追溯的项目资料，不是改写个人长期记忆的授权。

### 2. 建骨架

逐段写明本段要说清什么新内容，以及对应哪项证据和哪种画面。剧情顺序可以根据论证需要调整，不必机械照搬素材时间轴；但任何镜头和引文都必须真实存在，否则就要明确列为待补素材。

合并同一证据、同一解释的重复段，再安排人物处境、疑问或冲突进入的位置。基础现象解释完以后，应给观众继续听的新理由；不能长期复述画面，把决定本期理解的人物问题拖到最后。重排服从本期主题，不规定固定段数、揭示位置或删除比例；具体方法见 [作者声音与整稿推进](references/author-voice.md)。

### 3. 成稿

同时维护两份文本：

- `口播稿.md`：保留证据等级、画面锚点、停顿和制作旁注；
- `口播纯文本.md`：只保留真正念出口的正典文字。

去掉标记后，两份口播内容必须逐字一致。发音代理只进入配音的 `generation_text`，不得反向污染正典文字。

标注稿在相应段落旁提供非口播的段号、证据定位、判断范围与画面动作，需要时注明语义停顿；不能只有“详见另表”。论证映射应对应实际判断，落款等非论证内容无需强挂证据。不要为排版整齐拆散证据与解释，也不要习惯性在主语后加逗号。

成稿时执行[段内逐句承接](references/traditional-chinese.md#6-段内逐句承接已确认的狐久写作要求)：论证段在事实转解释、引文转判断、人物目的转行动、线索转推测处持续引导。先合并重复判断，再补缺少的推理，最后选择“而、也、才、却、因为、于是”等承接；不能为了精简删掉有作用的连接，也不能用“所以”把相关性写成因果。画面描写和收束段可以更轻，不按每段或每百字配额堆词。

### 狐久推断类口播：连续叙事硬规则

用户已明确要求：正文把支持线索和推断连续讲完，反证不要中途打断观感。除非本次用户明确要求辩论、辟谣或正反比较，后续狐久推断类稿件按此执行：

- 正文沿着证据、人物行动和推理向前推进；不在每个例子后插入「但这不等于」「还不能认定」「也可能只是」「仍需证明」等自我反驳、竞争解释或研究边界汇报。
- 反证、证据缺口、类比差异和可推翻条件完整保留在研究表、标注稿的非口播备注与审校记录中。确有必要让观众知道的限定，集中到结尾一小段；不把全部反证搬到结尾再开一轮辩论，也不强制每期加免责声明。
- 保留自然的「我推测、可能、如果」及原文必需的对象、年代和条件。删反证不能把猜想改成官方结论，也不能删掉会改变事实含义的限定；遇到错误就改命题或删论点，不能留到结尾才纠正。
- 改稿先读用户最新词面，保留其删改方向；除独立反证段，还要清掉散落在段尾、转场和总结里的同类打断。删后重写承接，检查主语、引文和因果是否仍完整。剧情自身的冲突、人物犹豫和自然转折不属于需要机械删除的反证。
- 送审前逐段做连续叙事检查，在 `editorial_submission_v2.counterexplanation_and_falsifier` 中记录反证保存位置、正文中途打断是否清零、结尾限定段的位置或无需保留的理由。仍有无必要的中途自我反驳，不能作为已完成改稿提交。

### 4. 审校

首次发给用户前完成整稿复盘，不能等用户指出一句后只修一句：

- 按“承诺与结构 → 事实及推导 → 措词与承接 → 节奏、情绪与收束”处理，实际记录要求见 [整稿审读记录](references/author-voice.md#整稿审读记录)。未解决的重复解释或因果缺口，不能用更多连接词掩盖。

- 开头直接给出本期大胆判断或清晰问题，第一段解释观众为何值得继续听；标题、钩子和结尾回答同一个承诺。预测措辞必须保留证据边界。
- 涉及人物行动时写清人物已知信息、利益或情感、来此的目的、可选道路及选择后果。逐条区分直接证据、类比、原型线索和推测；`A+` 是研究优先级，不是证据可信度。在非口播审校材料中记录最强竞争解释、反证、缺口与可推翻条件；正文遵守连续叙事规则。
- 区分剧情事实、镜头表现、作者解读和人物心理。镜头关注某人不自动证明角色的意图；听众受触动不自动证明歌者已找回自我。缺少中间依据时，补人物行动或台词，或收窄结论；“在我看来”及常识性心理解释不能替代证据。压缩转述也须保留能力、程度、目的、对象与条件。
- 全文检查“东西、什么、那样、选择、带来”等指称是否让听众无需倒回就知道具体人物、遗物、道路、行动与后果。不是机械禁词；引文保持原文，自然且明确的泛指可以保留。
- 全文执行[泛化评价措词复核](references/traditional-chinese.md#9-评价要说明具体作用不用分量作万能判断)：狐久旁白中评价意义、情感或重要性的“分量／份量”必须改写，官方逐字引文、术语和实际重量或数量含义除外。可写“关键、核心、重要”，但随后要交代关键在哪里；不能把词表替换当成完成审校。“多了一层……、有了……意味、值得在意、相互照应”等只作复核信号，逐项判断是否已说明具体作用，不扩大为一律禁词。
- 段内审校逐对检查相邻句，并在实际审校记录中保留“段号、前后句关系、保留或修改理由”；改动处给出原句与改句，并检查证据强度是否改变。措词审校记录命中位置、语义、替换或保留理由。两项均需全文执行，不能只修用户举出的那一句，也不能只填 PASS；细则见措词手册第五、九节。
- 结尾先回答核心问题，再从本期人物选择和具体后果升华。狐久项目以“那，以上，我是狐久，我们下期视频再见。”结束纯文本，不能省略或用泛用鸡汤替代。
- 情绪推进须来自本期处境、行动和后果，不连续用“温柔、震撼”等评价替代叙事，也不强添悲剧或成长。结尾完成一次连贯收束，检查是否连续几段重复总结；已有意象可回扣，但必须带来新的理解或余味，不另起一轮论证。

按 [v2 提交契约](../zhangyanfa-video-production/references/submission-contracts-v2.md) 保存绑定本稿、纯文本和实际审校证据的 `editorial_submission_v2`，通过后才首次提交。文笔、吸引力和论证强弱必须实际审读，不能由关键词计数或填写 PASS 代替。

运行 `scripts/audit_lore_script.py`，并显式传入正典纯文本与 `traditional_chinese_review.json`。默认启用 `author_voice_v1` 与 `traditional_chinese_v2`，不得退回 legacy 配置来冻结正式稿件。审校收据必须绑定当前稿件与诊断 SHA；逐句检查、指称与语体检查、段间与段内承接检查、泛化评价措词复核和全篇 1× 朗读都要完成，其中 `full_referent_register_reviewed` 必须为 `true`。`sentence_connection` 对应段内承接，`paragraph_progression` 对应段间推进，`word_choice_collocation` 对应措词；实际检查依据写入审校记录，不能只凭机检 PASS 声称完成。缺少任何一项，稿件都不能冻结。新规则约束后续成稿和返修，不追改旧批准或旧收据。

第二人称豁免只覆盖开头第一个核心问句本身。同一段问句之后的“你看/你会发现”仍属于正文，不能因为与钩子同段而通过。

风格计数只用于寻找可疑句子，不得为了清零“的”、抽象词或某种句式而改坏自然中文。出现以下任一情况，稿件不能通过审校：事实或词面仍有冲突；正文滥用第二人称；句法存在明确错误；逐句、段间、段内、措词或全篇 1× 审校尚未完成；正文超过用户明确规定的字数上限。

最新的逐句纠错高于早期批准。用户曾经整体通过一篇稿，不代表其中每一句都能直接收进措词手册；只有用户明确批准的具体改法，或者另一次独立逐词复核通过的句子，才能作为未来范例。

整稿审读也覆盖本轮新写的改法：不能只查历史原句、放过新例句中的重复或推断越界。承诺失配、未经依据的心理变化、无必要的重复解释，须在首次送审前修正；缺少实际整稿记录不得宣称审校完成。记录沿用现有审校材料及提交契约，不虚构新的机器校验字段；结构与文笔由实际审读判断，机检通过不替代这些要求。新规则约束后续创作和返修，不倒改已冻结稿件或审批。

不设“必须删掉 20%–35%”之类比例。删到每一段都有不可替代的新内容或必要作用为止；删除比例只能记录，不能据此判定稿件能否通过审校。

### 5. 审批与冻结

先向用户提交可读的完整稿件。用户批准当前版本后，写 `script_manifest.json`，绑定稿件、纯文本、证据表、画面需求和 QA 的 SHA-256。任何后续修改都产生新版本并重新审批。
