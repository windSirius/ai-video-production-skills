# 游戏剧情考据口播稿

把研究写成一篇能听懂、能配画、经得起核对的口播稿。判断力和证据先于固定模板；机检负责找风险，不能替作者决定一句中文是否自然。

总纲只有一句：先把人和事说清，再让概念参与解释；先让证据支持判断，再让人物选择承载价值。前半句约束句法与论证，后半句约束叙述立场与升华次序。

## 工作路径

先读取本期 `workspace_paths.json`，遵守[统一目录与素材规范](../zhangyanfa-video-production/references/workspace-layout.md)。稿件与审校放 `script/vNNN`，证据与研究放 `research/vNNN`。这里的 kind 由路径 resolver 解析，不是自行创建英文目录。 所有新版本先分配目录，再写文件；不自行发明另一套阶段路径。旧期 `legacy_indexed` 工作台用于导航，不视作新生产目录或新的审批权威。

## 输入与边界

开始前确认本期主题、观众看完以后应当明白什么、字数或时长上限、已有证据、反证、素材覆盖和素材缺口。优先读取上游 `evidence_ledger.tsv`、`source_coverage.json` 或同等文件；不要在本技能里重新下载、OCR 或建立镜头库。

处理事实或版本冲突时，读 [references/evidence-and-authority.md](references/evidence-and-authority.md)。任何新稿、改稿、压缩或正式审校，都必须完整阅读 [references/traditional-chinese.md](references/traditional-chinese.md)；这份手册同时保存用户已确认的反欧化正反例、叙事经验、措词标准和语料核验方法。出现“像 AI、絮叨、段落平均、同一判断换说法”时，再读 [references/author-voice.md](references/author-voice.md)。

## 冻结前必须满足的条件

1. 每个关键判断都能在原文或画面中找到依据，并标明页码或时间码；推断不得写成官方明示。
2. 全篇只回答一个核心问题。支线只有在会改变最终结论时才进入正文。
3. 每段原则上都应推进一项新内容：交代一件事、引用一段原文，或说明一层因果、反证、后果或判断。若没有新事实，也必须帮助观众理解前文、承接上下段或完成必要的情绪转折；否则删除。
4. 中文必须主干清楚、搭配自然、修饰得当、指代唯一、段间有承接。选词时还要分清所写的是人、众生、物件还是抽象概念，并确认它是旁白、人物台词、机构口吻，还是逐字引用的官方原文。全稿必须完成一次 1× 朗读。
5. 每段必须有可执行的画面需求。现有素材不足时记录 P0 缺口；可以先冻结稿件，但总控不得让未解决的 P0 缺口进入正式配画。
6. 用户明确批准当前稿件后，才能冻结 `script_manifest.json`。稿件、纯文本或证据变化后，旧批准立即失效。

## 第二人称：`hook_only`

- 开场第一个口播段可以用第二人称提出本期核心问句，例如“你真的看懂这场布局了吗？”
- 钩子之外，叙述层默认使用“我们”或第三人称。引文中的“你/你们”不计。
- 正文若无缘无故反复称呼观众，稿件不能通过审校；钩子使用第二人称本身不是错误。
- 钩子不必每期都用问句。现场、原文、结论或结果先行同样有效，以本期主题为准。

## 工作流

### 1. 立论

先用一句话写清本期要回答什么，再用一句话写出最终结论；随后列出最有力的证据、最强的反证、必要的因果和不能越过的边界。与最终结论无关的旁证留在研究附录，不写进口播正文。

跨期优先查已有证据索引，但重新核对版本、原文位置和是否仍成立。保留原文版本与引用定位，给旧预测登记命中、收窄、未决或失效，不能把旧期推测自动升级成官方事实。长期索引是可追溯的项目资料，不是改写个人长期记忆的授权。

### 2. 建骨架

逐段写明本段要说清什么新内容，以及对应哪项证据和哪种画面。剧情顺序可以根据论证需要调整，不必机械照搬素材时间轴；但任何镜头和引文都必须真实存在，否则就要明确列为待补素材。

### 3. 成稿

同时维护两份文本：

- `口播稿.md`：保留证据等级、画面锚点、停顿和制作旁注；
- `口播纯文本.md`：只保留真正念出口的正典文字。

去掉标记后，两份口播内容必须逐字一致。发音代理只进入配音的 `generation_text`，不得反向污染正典文字。

### 4. 审校

首次发给用户前完成整稿复盘，不能等用户指出一句后只修一句：

- 开头直接给出本期大胆判断或清晰问题，第一段解释观众为何值得继续听；标题、钩子和结尾回答同一个承诺。预测措辞必须保留证据边界。
- 涉及人物行动时写清人物已知信息、利益或情感、来此的目的、可选道路及选择后果。逐条区分直接证据、类比、原型线索和推测；`A+` 是研究优先级，不是证据可信度。记录最强竞争解释、反证、缺口与可推翻条件。
- 全文检查“东西、什么、那样、选择、带来”等指称是否让听众无需倒回就知道具体人物、遗物、道路、行动与后果。不是机械禁词；引文保持原文，自然且明确的泛指可以保留。
- 结尾先回答核心问题，再从本期人物选择和具体后果升华。狐久项目以“那，以上，我是狐久，我们下期视频再见。”结束纯文本，不能省略或用泛用鸡汤替代。

按 [v2 提交契约](../zhangyanfa-video-production/references/submission-contracts-v2.md) 保存绑定本稿、纯文本和实际审校证据的 `editorial_submission_v2`，通过后才首次提交。文笔、吸引力和论证强弱必须实际审读，不能由关键词计数或填写 PASS 代替。

运行 `scripts/audit_lore_script.py`，并显式传入正典纯文本与 `traditional_chinese_review.json`。默认启用 `author_voice_v1` 与 `traditional_chinese_v2`，不得退回 legacy 配置来冻结正式稿件。审校收据必须绑定当前稿件与诊断 SHA；逐句检查、指称与语体检查、逐段承接检查和全篇 1× 朗读都要完成，其中 `full_referent_register_reviewed` 必须为 `true`。缺少任何一项，稿件都不能冻结。

第二人称豁免只覆盖开头第一个核心问句本身。同一段问句之后的“你看/你会发现”仍属于正文，不能因为与钩子同段而通过。

风格计数只用于寻找可疑句子，不得为了清零“的”、抽象词或某种句式而改坏自然中文。出现以下任一情况，稿件不能通过审校：事实或词面仍有冲突；正文滥用第二人称；句法存在明确错误；逐句、段间或全篇 1× 审校尚未完成；正文超过用户明确规定的字数上限。

最新的逐句纠错高于早期批准。用户曾经整体通过一篇稿，不代表其中每一句都能直接收进措词手册；只有用户明确批准的具体改法，或者另一次独立逐词复核通过的句子，才能作为未来范例。

不设“必须删掉 20%–35%”之类比例。删到每一段都有不可替代的新内容或必要作用为止；删除比例只能记录，不能据此判定稿件能否通过审校。

### 5. 审批与冻结

先向用户提交可读的完整稿件。用户批准当前版本后，写 `script_manifest.json`，绑定稿件、纯文本、证据表、画面需求和 QA 的 SHA-256。任何后续修改都产生新版本并重新审批。
