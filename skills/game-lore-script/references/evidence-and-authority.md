# 证据与文本权威

## 证据层级

从强到弱依次为：游戏内正式文本与画面、官方网页或节目、可复核的官方宣传物、明确标注来源的可靠数据库、二手整理、推测与二创。高层证据与低层整理冲突时，以高层为准。

每个关键论点至少记录 `claim_id / 原文或画面 / 来源 / 页码或时间码 / 证据等级 / 核验状态`。网页存在分页、章节或卷册时，要核对实际支撑结论的页面，不能只保存入口链接。

## 不同文件各自决定什么

- 事实和论点：用户批准的稿件与其证据表；
- 措词和文气：用户最新一次逐句纠错，其次是明确批准的具体改法；整体通过的旧稿只能证明该版本可以继续制作，不能证明其中每句话都适合当作范例。后来的明确否定覆盖早期批准；
- 正典词面：`口播纯文本.md` 及其 `script_manifest.json`；
- 发音代理：配音模块的 `generation_text`，只服务合成；
- ASR：只用于发现遗漏、重复、错序和可疑发音，不负责认定人名、专名或称呼的正写法；
- 字幕断句与时间：后续经批准的最终 SRT；
- 成片时钟：已释放音频、最终 SRT 和帧率共同形成的时间契约。

用户若修改词面，应先形成稿件新版本，再判断是否需要重做配音；不能借修改字幕之名，私下改动已经冻结的稿件或配音词面。

把旧稿内容写进长期参考手册以前，必须重新逐词检查指称、搭配、语体和人物立场；不能让一轮生成的稿件反过来为自己的措词作证。

## 冻结

正式交接时，要记录路径、SHA-256、字符数、状态，以及用户批准这份文件的对应记录。文件名里的 `final`、修改时间或目录深度都不是权威；只有当前 manifest 的绑定关系才是。
